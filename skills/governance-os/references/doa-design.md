# تصميم مصفوفة الصلاحيات (DOA) — قبل أي إجراء

## لماذا أولاً
كل نقطة اعتماد في كل SOP تشير إلى سطر DOA. لو بنيت الإجراءات أولاً، ستكتب «يعتمد صاحب الصلاحية» — وهي عبارة فارغة تُبطل الإجراء كله.

## المشكلة التي ستجدها دائماً
الشركات لديها حدود متناثرة ومتعارضة في مستندات مختلفة (مصفوفة مالية قديمة · دورة مستخلصات · سقف عهدة). **لا تُصلح التعارض بالنقاش** — اسأل المستخدم: أقترح نسخة موحّدة واحدة، أم أترك الخلايا فارغة؟

## منهج اشتقاق العتبات
1. **ابحث عن المراسي**: أي رقمين مثبتين في مستند معتمد (مثلاً: 5,000 للصرف، 200,000 للتحويل). هذه نقطة البداية ومبرر الشرعية.
2. **ابنِ سلّماً منطقياً** حولها (4 مستويات نموذجية): مدير إدارة → نائب رئيس → نائبان معاً → الرئيس التنفيذي.
3. **غطِّ كل فئة قرار**، لا المالية وحدها: صرف · تحويل · شيك · مستخلص · عهدة · شراء · ترسية · عقد · أمر تغيير · خصم · شطب دين · سلفة · توظيف · نهاية خدمة · تمويل واستثمار · **استثناء** · **تعديل سياسة**.
4. **وسم كل سطر** `تصميم — يتطلب اعتماداً`، ونصّ صريح: بعد الاعتماد تصبح المرجع الوحيد، ولا يُطبَّق أي حد في مستند أقدم منفرداً.

## أعمدة السطر (كلها إلزامية)
`المعرّف · الفئة · القرار/الحد · الطالب · المراجع · المعتمد · الاعتماد النهائي · الدليل المطلوب · فحص فصل الواجبات`

**لا يوجد سطر بلا اعتماد نهائي.** خانة فارغة هنا = ثغرة رقابية.

## قاعدة الاستثناء (سطر إلزامي في المصفوفة)
- يُطلب **قبل** التنفيذ. الطلب بعد التنفيذ ليس استثناءً بل **تجاوزاً**.
- يعتمده صاحب صلاحية **أعلى بدرجة واحدة فقط** — لا قفز للأعلى تفادياً للمراجعة.
- **محدد المدة والقيمة والشرط.** لا استثناء مفتوح.
- **لا يعتمد أحد استثناءً من طلبه هو.**
- تكراره 3 مرات يعني أن **الإجراء معيب**، لا أن الموظف مخالف → يُعدَّل الإجراء.

## فصل الواجبات (SOD) — يُبنى مع الـDOA لا بعده
اكتب جدول **تعارضات ممنوعة** لا نصائح عامة. التعارضات الكلاسيكية التي يجب أن تظهر دائماً:

| ممنوع جمعه في شخص واحد |
|---|
| طلب الشراء + اختيار المورد |
| تحديد المواصفة + تقييم العروض |
| الاستلام + الدفع |
| إعداد القيد + مراجعته + اعتماده |
| إصدار أمر الدفع + تنفيذ التحويل البنكي (Maker/Checker) |
| تنفيذ العمل + اعتماد جودته |
| طلب التغيير + تحليل أثره |
| حيازة العهدة + تسويتها محاسبياً |
| منح الخصم + إصدار الفاتورة |
| إعداد مسير الرواتب + اعتماده + تحويله |
| منح صلاحية النظام + استخدامها |
| **الاعتماد الفني + الاعتماد المالي** |

كل تعارض مربوط بضابط `CTL` يمنعه **تقنياً** — لا اعتماداً على الالتزام الطوعي.

## كتالوج القرارات (DEC) — الجسر بين الحوكمة والإجراءات
لكل قرار: `الفئة · القرار · الموصي · المراجعة · الاعتماد · سطر DOA · الزمن`.
يُبنى **قبل** الإجراءات ويحدد «نوع القرار» قبل كتابة كيفيته.
