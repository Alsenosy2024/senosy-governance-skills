# قالب الإجراء الموحّد (SOP) — بلا استثناء

## الحقول الإلزامية (24 حقلاً)
```
id · title · dept · owner · approver · policy(السياسة الأم)
trigger(المُشغِّل) · start(حد البداية) · end(حد النهاية)
inputs[] · outputs[]
steps[] : (الدور, الفعل, النظام, الزمن, معرّف الضابط)
gates[] : (سؤال البوابة, مسار نعم, مسار لا)
approvals[] : (ما يُعتمد, صاحب الاعتماد, سطر DOA)
controls[] · sod · evidence[] · sla
exception · reject(مسار الرفض) · escalation
kpis[] · forms[] · registers[]
```

## قواعد الصياغة
- **الفعل يبدأ بفعل** ومسند لدور واحد. «يتم التنسيق» ليست خطوة.
- **البوابة سؤال** بإجابتين حصريتين، ومسار «لا» **مسار حقيقي** (إعادة · تصعيد · إيقاف) لا «يُعاد النظر».
- **كل نقطة اعتماد ← سطر DOA.** لو غير موجود، ولّده ووسمه.
- **SLA يُحسب من تاريخ اكتمال المستند** لا من استلامه ناقصاً. المستند الناقص لا يبدأ عدّاده. اكتب هذا صراحةً.
- **مسار الرفض برمز سبب** (مؤيدات ناقصة / كمية غير مطابقة / عقد منتهٍ…) لا برفض عام.
- **التصعيد بعتبة معلنة**: تجاوز X ← تنبيه للمالك؛ تجاوز Y ← تصعيد لنائب القطاع.
- **الاستثناء لا يُعالَج بالمرور اليدوي ولا بالتوقيع بعد التنفيذ.**

## العمليات التقاطعية (End-to-End) — بيت مستقل
لا تكرّرها داخل الإدارات. تكرارها = نسخ تتعارض بعد أول تعديل.
النموذجية في أي شركة: **دورة الدفع** (طلب→استلام→مطابقة ثلاثية→دفع) · **دورة الشراء** (طلب→منافسة→تقييم→ترسية) · **أمر التغيير** · **الرواتب** · **العهد** · **الفوترة والتحصيل** · **بدء وإقفال المشروع/المبادرة**.

## خرائط التدفق
- خريطة خطوات: سلسلة عمودية RTL بمسار دور لكل خطوة + رمز الضابط + النظام + الزمن.
- خريطة بوابات: لكل بوابة معيّن (diamond) بمساري نعم/لا.
- **بلا بتر.** الصندوق ينمو (انظر `build-engine.md` §6).

## اختبار القبول لأي SOP
> هل يستطيع موظف جديد تنفيذه **بلا شرح شفهي**؟
لو لا — الإجراء ناقص.
