# Reference Project Patterns

Use these patterns as starting points. Adapt to legal context, company maturity, and industry.

## Project A: Founder-Led SME Governance Build

Context:
- 50-300 employees
- Founder approves most decisions
- Informal policies
- Fast growth causing confusion

Main problems:
- Founder bottleneck
- Unclear approvals
- Weak middle management
- No consistent reporting

Recommended package:
- Current-state assessment
- Target org chart
- Delegation of authority
- Executive committee charter
- Finance/procurement/HR policies
- Top 10 SOPs
- KPI dashboard
- 90-day implementation plan

Key design choices:
- Keep committees limited.
- Delegate routine approvals.
- Protect high-risk decisions.
- Build management reporting cadence.

## Project B: Family Business Governance

Context:
- Family ownership
- Family members in management
- Succession sensitivity
- Mixing family, ownership, and executive decisions

Main problems:
- Role confusion
- Conflict of interest
- Informal intervention
- Succession risk

Recommended package:
- Family/ownership governance map
- Reserved matters
- Board/advisory board charter
- Family council charter if needed
- Conflict of interest policy
- Related-party transaction policy
- Delegation of authority
- Succession and key role continuity plan

Key design choices:
- Separate family decisions from company management decisions.
- Define reserved matters for owners.
- Document related-party approvals.

## Project C: Investor-Ready Startup

Context:
- Startup preparing for investment
- Fast decisions
- Weak documentation
- Founder-led execution

Main problems:
- Investor due diligence gaps
- No board cadence
- Weak financial controls
- Equity/authority ambiguity

Recommended package:
- Governance baseline assessment
- Cap table/reserved matters checklist
- Board/advisory cadence
- Authority matrix
- Finance controls
- Hiring and compensation approval rules
- Data room governance folder
- Risk register

Key design choices:
- Keep lightweight.
- Focus on auditability and investor confidence.
- Avoid heavy bureaucracy.

## Project D: Holding or Group Governance

Context:
- Parent company with subsidiaries
- Shared services
- Multiple CEOs/GMs
- Consolidated reporting needed

Main problems:
- Parent/subsidiary authority confusion
- Duplicate policies
- Weak group reporting
- Unclear shared services SLAs

Recommended package:
- Group governance model
- Parent/subsidiary decision rights
- Group authority matrix
- Board/sub-board committee structure
- Shared services model
- Group policy framework
- Consolidated reporting pack
- Risk and compliance taxonomy

Key design choices:
- Define what is reserved to the parent.
- Define what subsidiaries can decide.
- Create group minimum standards.
- Use SLAs for shared services.

## Project E: Regulated Company Governance Upgrade

Context:
- Financial services, healthcare, education, telecom, listed company, or government-related entity
- External regulator
- Compliance and audit pressure

Main problems:
- Regulatory findings
- Weak evidence
- Incomplete control records
- Board reporting gaps

Recommended package:
- Regulatory obligations register
- Board and committee charters
- Compliance framework
- Risk appetite statement
- Internal control framework
- Policies and SOPs mapped to regulations
- Evidence register
- Internal audit plan

Key design choices:
- Start from obligations and risks.
- Build evidence into every process.
- Define regulatory reporting ownership.

## Project F: Department-Level Governance

Context:
- User asks for governance for HR, IT, PMO, procurement, finance, or operations only.

Recommended method:
- Define department mandate.
- Map interfaces with other departments.
- Define department decision rights.
- Create RACI for core processes.
- Create policy/SOP set.
- Create KPIs and reporting cadence.
- Align with enterprise authority matrix.

Examples:
- PMO: project intake, prioritization, steering committees, change control, benefits tracking.
- Procurement: vendor onboarding, RFQ, evaluation, PO approval, contract handoff, vendor performance.
- HR: workforce planning, hiring approval, onboarding, performance, promotion, salary review, exit.
- IT: access management, change management, incident management, data governance, cybersecurity exceptions.
