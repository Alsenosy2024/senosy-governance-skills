# End-to-End Corporate Governance Methodology

## Purpose

Use this reference to run a full corporate governance project from kickoff to adoption.

## Phase 0: Project Setup

Objective:
Create a controlled consulting engagement with clear scope, sponsor, and acceptance criteria.

Key activities:
- Confirm scope and governance problem.
- Identify sponsor and approval authority.
- Define target entities, functions, and locations.
- Agree on deliverables and format.
- Create document request list.
- Create interview plan.
- Create communication cadence.

Inputs:
- Company profile
- Existing structure
- Strategy documents
- Bylaws/shareholder agreement if available
- Existing policies
- Existing job descriptions
- Audit reports
- ERP/HR/reporting system exports if available

Outputs:
- Project charter
- Stakeholder register
- Document request list
- Interview schedule
- Workplan

Acceptance criteria:
- Sponsor approves scope.
- Key stakeholders know what will be reviewed.
- Deliverables are named and dated.

## Phase 1: Current-State Assessment

Objective:
Understand how governance actually works today, not how documents say it works.

Workstreams:
- Document review
- Interviews
- Organization review
- Process review
- Decision review
- Authority review
- Controls review
- Reporting review

Recommended interviews:
- Owner/shareholder representative
- Board chair or equivalent
- CEO/general manager
- CFO/finance
- HR
- Procurement
- Operations
- Sales/commercial
- Legal/compliance
- IT/data/security
- Internal audit/risk if present
- Selected middle managers and frontline process owners

Diagnostic questions:
- Who makes strategic decisions?
- Which decisions are delayed most often?
- Which approvals are unclear?
- Which controls are bypassed?
- Which roles overlap?
- Which reports are trusted?
- Which committees exist only on paper?
- Where do employees escalate issues?
- What decisions depend on one person?
- What would break if the founder/CEO disappeared for two weeks?

Outputs:
- Current-state governance map
- Gap analysis
- Maturity score
- Risk/control gaps
- Decision bottleneck list
- Structure issues
- Quick wins

## Phase 2: Strategy and Operating Model Alignment

Objective:
Make governance serve the business model and strategic direction.

Activities:
- Translate strategic priorities into capabilities.
- Identify required decision speed and control level.
- Define centralization/decentralization principles.
- Define management rhythm.
- Decide which functions need independence.

Key design choices:
- Centralized vs decentralized procurement
- Centralized vs business-unit finance
- Independent risk/compliance vs embedded control
- Shared services vs departmental support
- Advisory board vs formal board
- Founder-led approval vs delegated management

Outputs:
- Target operating model
- Capability map
- Management rhythm
- Design principles

## Phase 3: Target Governance Model

Objective:
Define governance layers, decision forums, reporting lines, and accountability routes.

Recommended layers:
- Shareholder/ownership layer
- Board/advisory layer
- Executive layer
- Functional management layer
- Control and assurance layer
- Delivery/process layer

Design each layer by answering:
- What decisions belong here?
- What information is required?
- Who participates?
- Who approves?
- What gets escalated?
- What records must be retained?

Outputs:
- Governance model diagram
- Decision rights model
- Escalation model
- Committee/forum architecture
- Governance calendar

## Phase 4: Organization Structure

Objective:
Translate governance and operating model into a practical organization structure.

Steps:
1. Define major functions.
2. Define which roles need independence.
3. Group related capabilities.
4. Set reporting lines.
5. Check span of control.
6. Check segregation of duties.
7. Define department mandates.
8. Validate with leadership.

Common patterns:
- CEO with direct reports for Finance, HR, Operations, Commercial, Technology, Legal/Compliance.
- Control functions report functionally to board/audit committee where applicable.
- PMO reports to CEO or COO when strategic execution is weak.
- Procurement can sit under Finance, Operations, or Shared Services depending on risk and maturity.

Outputs:
- Target org chart
- Department mandates
- Role impact map
- Transition plan

## Phase 5: Authorities and Responsibilities

Objective:
Make decisions traceable and practical.

Build in this order:
1. Decision catalogue
2. Approval thresholds
3. Authority matrix
4. RACI for core processes
5. Escalation rules
6. Exception rules

Decision catalogue categories:
- Strategy
- Budget
- Procurement
- Contracts
- HR
- Finance/payments
- Sales/pricing
- Projects
- Risk/compliance
- Assets
- IT/data

Outputs:
- Delegation of Authority matrix
- RACI matrix
- Escalation protocol
- Exception log template

## Phase 6: Policies, Procedures, and Controls

Objective:
Create a document system that employees can follow and managers can enforce.

Policy writing order:
1. Governance policy/manual
2. Delegation and authority policy
3. Conflict of interest and ethics
4. Finance controls
5. Procurement
6. HR
7. Contracts/legal
8. Risk and compliance
9. Information/data security
10. Project governance

Procedure writing order:
1. High-risk/high-volume processes
2. Processes with recurring confusion
3. Processes with audit findings
4. Processes with customer/financial impact

Outputs:
- Policy register
- Policies
- SOPs
- Forms
- Control register
- Document control register

## Phase 7: Performance, Risk, and Reporting

Objective:
Make governance measurable.

Reporting layers:
- Board pack
- Executive dashboard
- Department scorecard
- Risk and compliance report
- Project portfolio report
- Issues and actions log

Metric types:
- KPI: performance and outcomes
- KRI: risk exposure and early warning
- KCI: control effectiveness
- SLA: service and process speed

Outputs:
- KPI/KRI library
- Reporting calendar
- Dashboard definitions
- Board/executive templates

## Phase 8: Rollout and Adoption

Objective:
Move governance from documents to behavior.

Adoption activities:
- Leadership approval session
- Manager briefing
- Policy awareness sessions
- Role-specific training
- Authority matrix walkthrough
- Committee launch meetings
- Document repository setup
- First-cycle reporting support

Outputs:
- Rollout plan
- Training material
- Communication messages
- Adoption checklist
- First 90-day support plan

## Phase 9: Review and Optimization

Objective:
Measure actual adoption and tune the framework.

Review after:
- 30 days: confusion and urgent fixes
- 90 days: adoption and reporting quality
- 180 days: governance effectiveness
- Annually: full maturity review

Outputs:
- Governance effectiveness review
- Updated maturity score
- Revised authority matrix
- Updated policy register
- Improvement backlog
